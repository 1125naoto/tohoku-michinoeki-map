    公開前UX整理: 周辺スポットを大分類＋Googleマップ詳細探索へ簡素化
    
    Owner実機QA（会津若松〜喜多方 ラーメン検索）で、実際には店舗が多い地域でも
    アプリ上の表示件数が少なく見える問題を確認。根本原因はclassification bugでは
    なくOSM/Overpassの登録・タグ品質・網羅率という構造的な制約であり、Google Maps
    並みの網羅性は保証できない。OSMデータをGoogle Maps並みにする方向へは進まず、
    「道の駅ナビ＝発見・車旅・旅程作成、Googleマップ＝網羅的詳細探索」という
    役割分担を明確にする方向でUXを整理した。
    
    現状監査（変更前）:
    - 周辺検索UIは カテゴリ→食subcategory(ラーメン/食堂/洋食/寿司/焼肉等)→検索範囲
      という構成で、「このボタンを押せば該当店舗が網羅的に表示される」という
      誤解を生みやすい構造だった。
    - PoiDetailSheet・ルートへのPOI追加・custom stopは今回の変更対象外
      （既存のまま。変更不要と確認）。
    
    変更（最小blast radius）:
    - 食べる(food)の細分類チップ(ラーメン/食堂/洋食/寿司/焼肉等)のみを一般ユーザー
      UIから撤去（観光/温泉/宿泊の細分類・雨の日向けフィルタは従来どおり維持。
      今回報告された問題が食べるカテゴリ固有だったため、変更範囲をそこに限定）。
      内部classificationロジック・POIデータは一切変更していない
      （一覧の各行には引き続き正しいジャンルをテキストで表示する）。
    - 各大分類（グルメ/観光/温泉・休憩/宿泊）に「🔍 Googleマップでもっと◯◯を探す」
      CTAを新設。検索地点が決まっていれば、検索実行前でも押せる（Overpass通信に
      依存しない）。大分類ボタンを押した瞬間にGoogleマップへ飛ばすのではなく、
      アプリ内候補表示とは別に「さらに探したい場合はこちら」という二段構造にした。
      URLはGoogle Maps URLs公式仕様（/maps/search/?api=1&query=）の範囲のみを使用。
      Google Places API・有料API・APIキーは追加していない。
    - 結果件数の文言を「周辺スポットをN件見つけました」→「周辺の主なスポットを
      N件見つけました」に変更し、網羅していないことを一言で伝える（長い注意書きは
      追加しない）。
    
    Route Plannerとの連携（アプリ内POIの「ルートに追加」、custom stop/custom final
    destination）は今回一切変更していない。
    
    テスト: TypeScript clean。Vitest 513/513 passed（新規2件: categoryDetailSearchUrl
    のURL生成・有料API不使用の確認）。既存e2e/poi.spec.tsのうち、食べるの細分類
    チップに依存していた3件を、内部classificationの正しさは一覧行テキストで
    確認する形、または細分類チップが残るカテゴリ(温泉・休憩)を使う形へ適切に
    アダプトした（regressionの保護対象自体は変更していない）。新規E2Eとして
    CTA表示・文言・食べるの細分類チップ不在を確認するテストを追加。
    
    iPhone QA: 本コードと無関係な既存の未変更テスト（poi.spec.ts先頭の基本テスト）
    が今回のセッション中に発生した深刻な機械負荷により同一のタイムアウトで
    失敗することを確認し、環境要因と特定した（コードの問題ではない）。

+/**
+ * 「Googleマップでもっと探す」CTA用の検索URL。
+ * アプリ内のOSM/Overpass由来POIは、道の駅ナビの主目的（道の駅発見・車旅・
+ * 周辺スポット発見・旅行ルート作成）に沿った「周辺に何がありそうか」の
+ * 発見用途であり、Google Mapsと同等の店舗網羅性は構造上保証できない
+ * （OSMの登録・タグ品質・網羅率に依存するため）。そのため大分類ボタンを
+ * 押した瞬間にGoogleマップへ飛ばすのではなく、アプリ内候補表示とは別に、
+ * 「さらに探したい場合はGoogleマップへ」という明確な二段構造のCTAを用意する。
+ *
+ * Google Maps URLs公式仕様（`/maps/search/?api=1&query=`）の範囲のみを使用。
+ * 検索半径を直接渡す公式パラメータは存在しないため、中心座標をqueryに含める
+ * （Google側が実際の検索範囲を決める）。Google Places API・有料APIは使わない。
+ */
+export function categoryDetailSearchUrl(keyword: string, origin: LatLng): string {
+  const q = `${keyword} ${origin.lat.toFixed(6)},${origin.lng.toFixed(6)}`;
+  return `https://www.google.com/maps/search/?api=1&query=${encodeURIComponent(q)}`;
