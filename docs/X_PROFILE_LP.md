# Xプロフィール用LP（/lp/）

Xのプロフィール（Webサイト欄）から誘導する、明るい縦長・販売LP。既存の公式トップ（`/`）と販売ページ（`/monitor/`）は上書きしない。

- 実装: `src/officialSite/lp.ts`（公式サイトのビルドが `lp/index.html` を追加で出力する）
- 素材: `public/official/lp/`（Owner提供画像から作ったもの）。アプリ画面は `public/official/img/` の**本物の画面**
- テスト: `src/officialSite/lp.test.ts`（Product Truth・Pricing Truth・構成・公開の扱い）／`scripts/lp-qa.mjs`（実ブラウザでスマホ・PC・リンク・速度・レイアウトずれ）
- 状態: **未公開**（公式ドメインへのデプロイは Owner の公開承認待ち）

## 公開URL案（Xプロフィールのサイト欄用）

```
https://michinoekinavi.jp/lp/?utm_source=x&utm_medium=profile&utm_campaign=lp1
```

購入記録の Client reference ID は `x_profile_lp1` になる（`utm_*` が無いときは既定の `lp1`）。LP は常に noindex（Xからの流入専用）。

## 公開手順（Owner 承認後）

```
npx vite-node scripts/build-official.ts        # dist-official/ を作る（lp/ を含む）
powershell -File scripts/deploy-official.ps1   # 公式サイトのリポジトリへ通常 push（force push しない）
```

## Product Truth: 生成画像との不一致と、その解消

Owner提供の画像（10枚）は機能紹介用の生成画像で、**アプリの画面部分が実在しない UI** だった。現行アプリのコード・実画面を一次証拠として照合し、次のように解消した。

| 不一致（元の画像） | 一次証拠 | 解消 |
|---|---|---|
| 道の駅詳細の「クチコミ」タブ（画像6・10） | `PoiDetailSheet.tsx`: 「評価・口コミはこのアプリには表示していません」（Googleマップへのリンク） | 画像ごと使わない。「口コミ・評価は Googleマップで」と明記 |
| 周辺スポットの「買い物」カテゴリ・「地元産直市場」（画像6・10） | `lib/poi.ts` `CATEGORY_LABEL` = 食べる／観光／温泉・休憩／宿泊 | 画像ごと使わない。カテゴリ名は `CATEGORY_LABEL` と一致をテストで固定 |
| アプリ内のターンバイターン案内画面（画像7・9） | アプリ内に案内機能は無い。`TripView.tsx` の「Googleマップで次の駅へ」で Googleマップを開く | 画像ごと使わない。「アプリの中にナビ画面はありません」と明記 |
| 下部タブ「地図・一覧・行きたい・設定」、「地図で探す／一覧で探す／エリアで探す」（画像1・3・4・8・9） | `App.tsx`: `type Tab = 'map' \| 'route' \| 'records'`（実機は 地図／コース／保存） | 画像ごと使わない。「タブ」の語を本文に出さない（テスト） |
| 「最適な順番」「最適なルート」（画像5・9） | 経路の順序調整はあるが「最適」とは言えない（実画面は「順番を調整しました」） | 使わない（テストで禁止） |
| 「お気に入りリスト」・ハートのアイコン（画像8） | アプリの機能名は「行きたい」 | 使わない |
| 「東北の美しい景色を〜」（画像9） | 全国版の販売ページ | 使わない |
| 「ナビアプリなどに連携」 | Googleマップのみ | 「Googleマップ」と明記 |

**使った Owner 素材（画面の絵を含まない部分だけ）**: ヒーロー上部（見出し・ロゴ・「全国1,237施設」。`lp-01`）、お悩みの画像（`lp-02`・人物と吹き出しで、アプリ画面を含まない）、写真の帯（`lp-b1`〜`b3`・ドライブの写真）。
**アプリ画面はすべて本物**（11枚）: 地図（全国・県）、凡例、達成状況、タップで開く詳細、コース選択、行程、周辺スポット、コース作成後のボタン、出発後の画面。

画像の「次のページで〜」ボタンは、HTMLの実ボタンに置き換えた（行き先と名前が一致。お悩みの画像のボタンだけは、画像の上に実リンクを重ねている）。

引用しているボタン名はすべてソースで実在を確認済み（`lp.test.ts` が毎回確かめる）: 訪問済みにする／行きたいにする／スタンプ取得済みにする（`StationSheet.tsx`）、この駅でコース作成（`RouteSelectBar.tsx`）、このコースで出発・Googleマップで全体を確認・地図で順番を見る・このコースを保存・立ち寄り先・順番・時間・道路の希望を変更する（`RouteResults.tsx`）、Googleマップで次の駅へ・到着した（`TripView.tsx`）。

LPの料金表示: ヒーローの価格の丸（HTML）、購入欄の月額・年間の2つのカード、継続課金・解約・返金・Stripe決済画面の表示名の説明が、**購入ボタンより前**にある。上部の「今すぐ始める」は決済リンクではなく、この購入欄への移動。

### 切替が働かなかった場合のリスク（Ownerの把握用）
- 購入者に不利になる方向ではない（切替が設定されないと250円のまま）。ただしLPは「3か月目から500円」と約束しているので、**最初の月額購入が入ったら、3回目の支払いの前に Subscription Schedule が付いたこと（runner.log の `configured`）を確認する**。
- 実行はOwnerのPCに依存する（PCが長期間オフだと設定が遅れる。3か月目の前に設定されれば問題ない）。
